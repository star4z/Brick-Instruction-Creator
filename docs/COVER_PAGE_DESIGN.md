# Front & Back Cover Pages — Official LEGO-Style Editorial Design Specification

## 1. Overview & Goals

The front cover of a manual generated by **Brick Instruction Works** follows the clean, editorial composition of modern official LEGO instruction booklets:

- **Minimal, uncluttered page canvas** inheriting the active theme (or optional user-uploaded background image) with generous visual breathing room.
- **High-quality, page-filling hero 3D render** of the completed model centered across the page, framed with camera-space tight bounding-box projection, studio 3-point + ABS plastic specular shading, refined seam lines, and a camera-accurate soft studio floor shadow.
- **Top-left identity column**:
  - Optional **Creator Logo** image uploaded by the builder, positioned cleanly above the title.
  - **Model Name** in bold editorial typography directly below the creator logo (or at top-left if no logo is set).
  - **Optional Subtitle** directly underneath the model name (rendered only when non-empty).
- **Top-right series / theme slot**:
  - Optional **Series / Theme Logo** (such as a series wordmark, subtheme badge, or faction emblem), right-aligned at the top-right corner.
- **Bottom-right non-editable program attribution & QR code**:
  - Fixed, non-editable **Brick Instruction Works** icon and attribution card displaying `"Made with"`, the unified single-line **`Brick Instruction Works`** title, and `"Scan QR to visit the website"` with a directional arrow pointing to the adjacent scannable **QR code** pointing to `https://star4z.github.io/Brick-Instruction-Creator/`.
  - **Clickable in both live preview and exported PDF**: in the live viewer it opens in a new tab without triggering page panning; in the exported PDF it embeds a standard PDF 1.4 `/Subtype /Link` URI annotation over the attribution card and QR code bounding box.
- **Back cover non-editable program attribution**:
  - Centered **Brick Instruction Works** logo and fixed, non-editable `"Made with Brick Instruction Works"` credit (clickable in both live preview and exported PDF). Users may still apply or clear a custom background image for the back cover.

## 2. Layout Architecture

Both the live HTML preview (`src/studioRuntime.ts`) and the high-DPI PDF canvas renderer share a single deterministic layout calculator in [`src/cover/coverLayout.ts`](../src/cover/coverLayout.ts).

```
┌────────────────────────────────────────────────────────────────┐
│ [Creator Logo]                           [Series / Theme Logo] │
│ Model Name                                                     │
│ Optional Subtitle                                              │
│                                                                │
│            ╔══════════════════════════════════════╗            │
│            ║                                      ║            │
│            ║    High-Quality Page-Filling Hero    ║            │
│            ║      3D Model Render + Soft Floor    ║            │
│            ║            Studio Shadow             ║            │
│            ║                                      ║            │
│            ╚══════════════════════════════════════╝            │
│                                                                │
│                   [Icon | Made with               ]  [  QR  ]  │
│                   [     | Brick Instruction Works ]  [ Code ]  │
│                   [     | Scan QR to visit ...  → ]            │
└────────────────────────────────────────────────────────────────┘
```

### Zone Proportions
- **Outer Margin (`pad`)**: ~4.8% of the page's shorter dimension (respecting print safety margins).
- **Top-Left Column**: Max width ~46% of inner width.
  - Creator Logo (optional): max height ~10% of shorter page edge, max width ~22% of page width, aspect-ratio preserved (`contain`, left-aligned).
  - Model Name: bold editorial sans-serif (~4.2%–5.0% of shorter page edge), wraps gracefully up to 2 lines.
  - Subtitle (optional): muted weight (~2.1% of shorter page edge), omitted entirely when blank.
- **Top-Right Series / Theme Logo**: Optional, max height ~11.2% of shorter page edge, max width ~44% of inner width, aspect-ratio preserved (`contain`, right-aligned).
- **Hero Render Region**: Spans ~94.8% of page width (`left: 2.6%`, `right: 2.6%`) and ~65%–75% of page height, sitting cleanly behind the corner overlays (`z-0` vs `z-10`) so tall masts, antennae, or wings can rise naturally into the open center space between the top-left and top-right headers.
- **Bottom-Right Program Attribution & QR Code (Non-Editable)**:
  - Always rendered and anchored to bottom-right `(right: pad, bottom: pad)` — cannot be toggled off in the editor or via saved/imported `.biw` files.
  - QR code square card: side length ~10% of the page's shorter dimension (approx. 18–21 mm on US Letter/A4), white background with quiet zone and subtle border for universal camera scannability on both light and dark themes.
  - Program attribution card: matching-height rounded card containing the 3-plume logo mark alongside three crisp lines: `"Made with"` eyebrow, unified single-line bold **`Brick Instruction Works`** title, and `"Scan QR to visit the website"` with a vector right arrow pointing directly at the QR card.
  - In PDF export, the card width expands cleanly leftward if a wide theme font (such as Monospace or Slab) measures wider than the baseline width, and the combined rendered bounding rectangle is registered as a clickable link in both DOM (`<a>`) and PDF (`/Annot /Subtype /Link`).

## 3. Photorealistic Studio Hero Rendering Pipeline (`src/cover/studioPhotoRenderer.ts`)

To achieve a publication-grade LEGO studio photography look on the Cover Page (and Build Complete showcase page) with zero external dependencies and full WebGL 1.0 compatibility:

1. **Micro-Beveled Hero Brick & Smooth Stud Geometry (`heroQuality: true`)**:
   - Procedural bricks generate subtle `0.48 LDU` 45° chamfered edge bevels and corner facets so every brick seam catches crisp studio softbox catchlights.
   - Studs and cylinders render at 16+ segments with smooth per-vertex radial normals and a chamfered top bevel ring so specular highlights wrap smoothly around every stud.
2. **Telephoto Studio Perspective Camera (`computeStudioTelephotoCamera`)**:
   - Uses a long product-photography telephoto lens (`~18.5°` vertical FOV, equivalent to ~115mm macro lens) fitted tightly to the model's exact projected silhouette so models of any proportion fill the cover edge-to-edge while retaining authentic physical depth.
3. **Triple 24-Bit RGBA-Packed Studio Softbox Shadow Maps**:
   - Renders three offscreen depth shadow maps with zero float-texture extensions needed:
     - **Key Softbox** (`1024×1024`, high front-right relative to camera)
     - **Fill Softbox** (`768×768`, front-left studio bounce)
     - **Overhead Light-Tent Dome** (`768×768`, top vertical occlusion under overhangs and decks)
   - Sampled with per-pixel rotated Vogel-disk PCF kernels (`12–16` taps) and normal-slope-scaled bias for buttery-soft, artifact-free self-shadows across studs, overhangs, and stands.
4. **Physically-Based LEGO ABS Plastic Shading (Linear HDR → ACES Filmic → sRGB)**:
   - Converts brick albedo from sRGB to linear light space (`pow(c, 2.2)`).
   - Evaluates Cook-Torrance **GGX** microfacet specular + energy-conserving diffuse across 3 camera-relative studio lights (warm-daylight key, cool-neutral fill, crisp back-rim strip) with ABS dielectric reflectivity (`F0 = 0.046`, IOR ≈ 1.54).
   - Samples a procedural tabletop **studio softbox cyclorama environment** via Schlick Fresnel reflection so flat walls, dark display stands, and clear polycarbonate bricks reflect realistic overhead softboxes and studio floor bounce.
   - Applies **ACES Filmic tone mapping** and sRGB gamma encoding for rich, photographic highlights and deep non-crushed darks.
5. **3D Shadow-Catcher Studio Floor Plane**:
   - Rendered in 3D at `y = minY - 0.12` receiving all three softbox shadow maps with proximity-weighted contact darkening (dark crisp contact shadow right under grounded feet/stands + wide feathered penumbra under overhanging hulls/wings) and transparent alpha feathering so it blends onto any theme or custom background.
6. **Screen-Space Ambient Occlusion (SSAO) Crevice Pass**:
   - Renders a linear view-space depth pass and evaluates a 16-sample depth-thresholded rotated screen-space occlusion kernel to softly darken stud bases, brick-to-brick joints, and recessed corners without creating silhouette halos.
7. **High Resolution, Interactive Orbit & Graceful Fallback**:
   - Live cover preview renders up to `1600px` wide; PDF export renders up to `2000px` wide. Both reuse the cached hero beveled mesh and rendered snapshots across UI edits, and gracefully fall back to `WebGLBrickEngine` if FBOs are unavailable.
   - In **`Camera`** mode on both Front Cover and Build Complete pages, dragging directly over the hero render runs `StudioPhotoRenderer.renderToCanvas(..., { fastInteractive: true })` (skipping per-frame SSAO FBO churn and `toDataURL` encoding) for smooth 60fps live 3D orbiting, paired with the same 4 isometric **Cube + Camera** angle presets (`45°`, `135°`, `225°`, `315°`), **Zoom** (`− / % / +`), and **Reset Camera** controls used on step pages. Elevation remains clamped above the studio floor (`4°..60°`) so floor shadows stay grounded, and releasing the drag commits a full-resolution snapshot. Content, logos, toggles, and backgrounds live separately under **`Page`** mode.

## 4. Pure-TypeScript QR Code Generator (`src/cover/qrCode.ts`)

- Zero external dependencies (Neocities-safe, tiny bundle footprint).
- Implements ISO/IEC 18004 Byte-mode QR encoding (Versions 1–6, EC levels `L` and `M`) with GF(256) Reed-Solomon error correction, interleaved blocks, finder/alignment/timing patterns, 15-bit BCH format information, and all 8 mask evaluations with standard penalty scoring.
- Encodes `https://star4z.github.io/Brick-Instruction-Creator/` (52 bytes) into a crisp **Version 4-M** (33×33 modules, 15% error correction) QR code rendered as a single-path SVG in the DOM and sharp pixel-aligned rectangles in the PDF canvas.

## 5. Clickable PDF Link Annotations (`src/export/pdfBinary.ts`)

The pure-JS PDF 1.4 binary builder supports per-page URI link annotations (`PdfPageLink`):

- Each link rectangle in top-left canvas pixel coordinates `(x, y, w, h)` is converted to PDF bottom-left point coordinates `[llx, lly, urx, ury]`.
- Page objects with links emit `/Annots [ <annotId> 0 R ... ]`, and each annotation object writes:
  ```pdf
  << /Type /Annot /Subtype /Link /Rect [llx lly urx ury] /Border [0 0 0] /H /I /A << /Type /Action /S /URI /URI (https://star4z.github.io/Brick-Instruction-Creator/) >> >>
  ```
- Applied to the bottom-right program logo + QR badge on the Front Cover, as well as the program logo on the Back Cover.

## 6. Data Model & Persistence

`coverMeta` (persisted in undo history, IndexedDB session preferences, and `.biw` project exports):

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `title` | `string` | `''` (falls back to `model.title`) | Model name shown at top-left |
| `subtitle` | `string` | `''` (hidden when empty) | Optional subtitle below model name |
| `az` | `number` | `34` | Hero camera azimuth in degrees |
| `el` | `number` | `18` | Hero camera elevation in degrees (`4`–`60`) |
| `zoom` | `number` | `1.0` | Hero render scale (`0.70`–`1.40`) |
| `bgSrc` | `string \| null` | `null` | Optional full-page background image data URL |
| `creatorLogoSrc` | `string \| null` | `null` | Optional creator logo image above model name (top-left) |
| `themeImageSrc` | `string \| null` | `null` | Optional series / theme logo (top-right) |
| `showText` | `boolean` | `false` on wordless imports (`true` for legacy `.biw`) | Toggles top-left Model Name & Subtitle; when `false`, the hero 3D render expands upward into the freed title area while keeping the bottom-right attribution + QR intact |
| `showQrCode` | `true` (locked) | `true` | Non-editable; always normalized to `true` so the scannable QR code is always shown |
| `showProgramBadge` | `true` (locked) | `true` | Non-editable; always normalized to `true` so the program attribution card is always shown |

`backMeta` (persisted in undo history, IndexedDB session preferences, and `.biw` project exports):

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `subtitle` | `string` (locked) | `'Made with Brick Instruction Works'` | Non-editable; always normalized to `BACK_COVER_CREDIT` |
| `bgSrc` | `string \| null` | `null` | Optional full-page background image data URL (uploadable & clearable in Back Cover `Page` mode) |

`completeMeta` (normalized via `normalizeCompleteMeta()` alongside `coverMeta`):

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `title` | `string` | `'Build Complete!'` | Showcase heading |
| `subtitle` | `string` | `'Ready for display!'` | Showcase subtitle |
| `az` | `number` | `315` | Hero camera azimuth in degrees |
| `el` | `number` | `28` | Hero camera elevation in degrees (`4`–`60`) |
| `zoom` | `number` | `1.0` | Hero render scale (`0.70`–`1.40`) |
| `bgSrc` | `string \| null` | `null` | Optional full-page background image data URL |
| `showText` | `boolean` | `true` | Toggle heading & subtitle visibility |
| `showFireworks` | `boolean` | `true` | Toggle celebratory fireworks backdrop |
