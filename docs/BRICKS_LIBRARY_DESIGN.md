# Dedicated Bricks Library Screen & Searchable 3D Parts Preview — Design Specification

## 1. Motivation & UX Problems Solved

Previously, Bricks Library controls were embedded directly inside the slide-out menu drawer and suffered from four UX and transparency issues:

1. **Silent 15-Part Fallback (~34 Files)**: Clicking **Fetch Missing Parts Online** with no model loaded silently fell back to a hardcoded list of 15 basic brick IDs, which expanded into ~34 `.dat` files (15 top-level parts + 19 internal subparts/primitives) with no explanation of why only 34 files were saved.
2. **Ambiguous "Missing Parts" State Without a Model**: The button always said *"Fetch Missing Parts Online"* even when no model was loaded, leaving users unclear on what was "missing".
3. **Confusing "Clear" Button Placement Next to "Import"**: Positioning a `Clear` button directly beside `Import .zip / .dat` implied it cleared the last import action, when in reality it wiped the entire saved Bricks Library from IndexedDB without confirmation.
4. **No Library Inspection or Search**: Users had no way to preview what parts were currently loaded (saved, embedded `.io`, or built-in), search for a part by ID or name, or fetch specific parts/packs on demand.

---

## 2. Information Architecture

### 2.1 Menu Drawer Entry
- The slide-out menu drawer (`#menuDrawer`) displays a clean **`Bricks Library →`** navigation button (`#menuBricksLibBtn`) matching **Page Setup**, **Style**, and **Parts List Setup**, with no inline status summary or description copy underneath.
- Quick actions inside **Model Issues** (`#errorsModal`) open the dedicated Bricks Library screen directly rather than scrolling the menu drawer.

### 2.2 Dedicated Bricks Library Screen (`#bricksLibraryModal`)
A responsive full-height modal (`max-w-4xl`) organized into two top-level tabs plus a shared live progress bar (with a working **Cancel** button during online fetches):

#### Tab 1: **Browse & Search** (`#libTabBrowse`)
- **Search Bar**: Real-time debounced search (`#libSearchInput`) matching part ID, human-readable name, and category. Search normalization (`normalizeLibrarySearchText`) unifies spacing and multiplication signs (`2 x 4`, `2×4`, `2x4`) so official LDraw names match naturally.
- **Direct Search-to-Fetch Shortcut**: When a user types a specific LDraw part ID (e.g., `3010` or `3626cp01`) that is not yet in the saved library, an inline banner offers one-click **Fetch `<id>` Online**.
- **Filters**:
  - **Scope pills**: `All`, `Built-in` (unified scope encompassing procedural shapes + all Official LDraw + all Unofficial & Studio parts), `Official LDraw` (bundled official catalog), `Unofficial & Studio` (bundled unofficial/Studio catalog), `Saved`, `Embedded .io` (when present), `In Model` (when a model is loaded), and `Missing` (when the loaded model has missing shapes).
  - **Category selector**: `All Categories`, `Bricks`, `Plates`, `Tiles`, `Slopes & Curves`, `Technic & Bars`, `Minifigures`, `Windows & Panels`, `Other Parts`.
  - **Available Color Filter (`#libColorFilterWrap`)**: Searchable perceptual color popover organized by finish (`In Current Model`, `Solid`, `Transparent & Satin`, `Metallic, Pearl & Chrome`, `Rubber & Glow`) showing only LEGO colors with available parts and live part counts per color. Selecting a color filters the library strictly to parts actually produced in that LEGO color (`availableColorId`), automatically syncs the 3D preview color to match, and offers a one-click `×` clear button that restores the previous preview color.
  - **Helpers toggle**: `Show subparts & primitives` (off by default so internal `s/...` subparts and geometric primitives like `box5` or `4-4edge` don't clutter the browse grid).
- **Unified Built-in Catalog (`public/parts-catalog/*.json` + `src/engine/partsCatalog.ts` + `src/engine/partColors.ts`)**:
  - Generated from the public mirrors by `scripts/build-parts-catalog.mjs` (`official.json`: ~23.8k official LDraw parts, ~337 KB gzipped; `unofficial.json`: ~5.9k additional LDraw Unofficial & BrickLink Studio parts not in official, ~101 KB gzipped).
  - **Part Color Availability Index (`public/parts-catalog/part-colors.json`)**: Generated by `scripts/build-part-colors.mjs` from Rebrickable's public daily CSV dumps (`elements.csv.gz`, `inventory_parts.csv.gz`, `part_relationships.csv.gz`), translating Rebrickable color IDs to standard LDraw (`LDConfig.ldr`) color IDs. Indexes ~6.3k catalog parts across ~134 real-world LEGO colors (~46 KB gzipped) without guessing colors for printed/decorated parts, and loads lazily alongside `official.json` / `unofficial.json`.
  - Contains IDs, clean titles, and helper/alias flags only — no 3D `.dat` geometry — and is preloaded lazily when the side menu or Bricks Library opens, keeping initial app load untouched.
  - All official and unofficial catalog parts are unified under the `Built-in` scope and count (`isBuiltInLibraryItem()`), while preserving dedicated `Official LDraw` and `Unofficial & Studio` filter pills and part badges.
  - Once loaded, catalog titles also enrich `getHumanPartName()` across the app.
- **Lazy Auto-Fetching 3D Thumbnail Grid**:
  - Paginated (48 items per batch + *"Load more parts"* button / infinite scroll) so browsing ~30,000 parts or a full `complete.zip` import stays responsive.
  - Uses `IntersectionObserver` + a 4-per-frame `requestAnimationFrame` WebGL snapshot queue (`libThumbCache`, bounded LRU up to 320 entries) with the full LDraw color picker.
  - **Viewport Auto-Fetch**: When a built-in official or unofficial part scrolls into view without locally cached `.dat` geometry, a dedicated background viewport fetcher (`pumpLibThumbFetchQueue`) batches up to 6 visible parts at a time via `fetchLDrawDependencyGraph` (with `preferUnofficial` mirror routing so unofficial parts hit the unofficial mirror first), caches the downloaded `.dat` and textures to IndexedDB silently, and renders the crisp 320×320 3D thumbnail in place without rebuilding the grid DOM or showing "Tap to preview" placeholders. Scrolling away or closing the modal aborts stale fetches cleanly, and offline/404 states settle gracefully without spinning indefinitely.
  - Renders crisp HiDPI 320×320 thumbnails using the active theme's **Style → Rendering Style** (`stepLighting`: `None` flat unlit, `Standard` 3-point ABS plastic shading, or `Studio` micro-bevels & soft shadows via `StudioPhotoRenderer`; plus `Outline All Parts` and `Outline Weight`) with style-keyed caching and automatic cache invalidation when the rendering style or theme changes.
  - Procedural built-in shapes render authentic geometry offline without network access (slopes, inverted slopes, smooth curved slopes, L-shaped corners, centered/end-stud jumpers, slotted grilles, rounded/quarter-round/holed tiles, Technic pin holes & `+`-section axles, open hollow window frames, SNOT brackets, horizontal/vertical C-clips, contoured seats, flanged train wheels/holders, and sculpted minifigure limbs & domed helmets).
- **On-Site Paginated 3D Part Chunks (`thirdparty/parts-chunks/` + `src/engine/partsChunks.ts`)**:
  - Built-in Official LDraw and Unofficial/Studio `.dat` geometry is packed by `scripts/build-parts-chunks.mjs` into lexicographically sorted, gzip-compressed `.bin` chunks (`c000.bin`, `c001.bin`, …, sized ~1.5–2.5 MB each for fast lazy fetching and well under the 100 MB Neocities Supporter per-file / 50 GB total hosted-site caps) plus a compact `manifest.json` storing `[first, last]` key ranges, stashed in the `star4z/Brick-Instruction-Creator-thirdparty` git submodule (`thirdparty/`) and copied into `dist/parts-chunks/` at build/deploy time.
  - At runtime, `createOnSitePartsChunkLoader` binary-searches `manifest.json` and lazily downloads only the exact chunk(s) needed from the app's own origin (`./parts-chunks/`), decompressing with `DecompressionStream('gzip')` and caching in memory + IndexedDB (**Downloaded**) with **zero external third-party calls** for built-in parts. External mirrors remain only as an optional fallback for unknown/custom part IDs.
- **Interactive 3D Part Preview Inspector (`#libPreviewPane`)**:
  - Displays a HiDPI 880×880 WebGL render following the active **Style → Rendering Style** (lighting mode, outlines, and outline weight) with interactive orbit/flip controls.
  - On narrow/mobile screens (`< md`), selecting a part opens Part Preview as a dedicated full-sheet page (`syncLibMobilePreviewPageState`), hiding the top tabs (`#libTopTabsBar`), search/filter controls (`#libBrowseFiltersBar`), and parts grid (`#libBrowseGridWrap`) so irrelevant list-filtering controls never clutter the single-part view; tapping **Back to Parts** (`#btnCloseLibPreview`) or pressing `Escape` returns to the parts list with search/filters and scroll position preserved. On desktop (`md:` and up), it remains a side-by-side inspector alongside the live-filtered parts grid.
  - The 3D preview color popover (`#libColorPopover`) is anchored dynamically to whichever visible trigger opened it (Browse header or Part Preview page).
  - Clicking **`N subfile refs`** (`#libInspectorSubfilesBtn`) returns to the Bricks Library grid filtered specifically to those referenced subfiles (automatically showing subparts & primitives) with a removable `#libSubfileFilterBanner`.
  - Clicking an uncached built-in part promotes it to the front of the background fetch queue (`requestPriorityLibPartFetch`) and renders its 880×880 3D preview as soon as its geometry arrives.
  - Shows part ID, human name, kind (`Part`/`Subpart`/`Primitive`), category, clickable subfile reference count, all source badges (`Embedded (.io)`, `Downloaded`, `Built-in Shape`, `Official LDraw`, `Unofficial & Studio`, `In Current Model` / `Missing in Model`), and a perceptually sorted **"Available colors (N)"** swatch strip (collapsible beyond 24 colors) where clicking any swatch previews the part in that real-world color.
  - Redundant manual per-brick **Save to Local Library** / **Fetch Online** buttons are omitted for built-in parts; only **Retry Downloading** (when offline/failed) and **Remove `<id>.dat` from Downloaded Cache** (when cached in IndexedDB) are shown.

#### Tab 2: **Fetch & Import** (`#libTabManage`)
Organized into four clearly separated cards:

1. **Current Model Card** (Context-Aware via `getModelFetchCopy`):
   - **No model loaded**: Explicitly reads *"No Model Loaded"* and disables the model-missing CTA (never says *"Fetch Missing Parts"* without a model).
   - **Model loaded with missing shapes**: Shows the model title, exact count, preview chips of missing `.dat` IDs, and an enabled **`Fetch N Missing Model Parts Online`** CTA.
   - **Model loaded with built-in approximations only**: Offers an optional **`Fetch N Exact LDraw Shapes for Model`** upgrade.
   - **Model complete**: Displays **`All Model Parts Loaded ✓`** (disabled).
2. **Download Starter Packs or Specific Parts Online**:
   - Mirror selector covering every public source (`Official LDraw Library (Daily Sync · GitHub)`, `Official LDraw Library (GitHub Pages Mirror)`, `Classic LDraw Mirror (GitHub)`, `Official LDraw Library (jsDelivr CDN)`, `LDraw Unofficial & Studio Parts (GitHub)`, or custom base URL). The selected source is tried first and all remaining sources stay in the automatic fallback chain.
   - Four transparent **Curated Starter Packs** (`ONLINE_STARTER_PACKS`, 102 unique official parts total):
     - *Bricks & Plates* (34 parts)
     - *Tiles, Slopes & SNOT* (28 parts)
     - *Technic, Bars & Clips* (24 parts)
     - *Minifigures & Windows* (16 parts)
   - Each pack shows live `saved / total` progress and an individual fetch button, alongside a **Fetch All Starter Packs** button.
   - **Fetch Specific LDraw Part IDs** input accepting comma-, space-, or newline-separated IDs.
3. **Import Local Files (`.zip` / `.dat`)** — Standalone Card:
   - Contains only the **`Import .zip / .dat Files…`** action and an external link to `https://library.ldraw.org/updates?latest` for downloading the full ~20,000-part `complete.zip`.
   - No destructive button sits next to Import.
4. **Saved Library Storage** — Visually Separated Danger Zone:
   - Red-tinted bottom card displaying exact storage breakdown (`X parts + Y subparts/primitives (Z files · T textures)`).
   - Explicitly explains that clearing only removes saved fetched/imported library files from browser IndexedDB and does **not** affect the loaded model, embedded `.io` shapes, or built-in parametric shapes.
   - Uses a button clearly labeled **`Clear Entire Saved Library`** backed by an inline 2-step confirmation (`Yes, Clear Saved Library` / `Cancel`).

## 3. Data Classification & Pure Engine Modules (`src/engine/bricksLibrary.ts`, `src/engine/partsCatalog.ts`, `src/engine/partColors.ts`)

All pure classification, indexing, catalog loading, color-availability filtering, search, and UI copy rules live in `src/engine/bricksLibrary.ts`, `src/engine/partsCatalog.ts`, and `src/engine/partColors.ts` (covered by unit tests in `src/engine/__tests__/bricksLibrary.test.ts`, `src/engine/__tests__/partsCatalog.test.ts`, and `src/engine/__tests__/partColors.test.ts`):

- **`classifyDatEntryKind(key, lines, title)`**: Inspects `0 !LDRAW_ORG` headers first (`Part`/`Shortcut`, `Subpart`, `Primitive`/`48_Primitive`/`8_Primitive`), falling back to path prefixes (`s/`, `48/`, `8/`), `~`-prefixed helper titles, and standard LDraw primitive naming patterns.
- **`loadPartsCatalog()` / `parseCatalogPayload()` / `mergeCatalogEntries()`**: Lazily fetches `public/parts-catalog/official.json` and `unofficial.json`, validates the format, precomputes normalized search haystacks, and merges them with official entries taking priority over duplicate unofficial IDs.
- **`loadPartColorsCatalog()` / `parsePartColorsPayload()`**: Lazily fetches `public/parts-catalog/part-colors.json`, normalizes part IDs, builds `byPart` / `byPartSet` lookup maps and per-color `partCountByColor` totals.
- **`buildLibraryIndex(input)`**: Deduplicates `BL_Item_No` aliases sharing the same line-array reference, merges `embeddedDatRaw`, `userLibRaw`, `PARTS_CATALOG`, `onlineCatalog`, `partColors`, and current model part sets, and produces accurate `LibraryStats` separating top-level `savedParts` from `savedHelpers` (subparts + primitives) alongside `catalogOfficialParts` and `catalogUnofficialParts`.
- **`filterLibraryItems(items, options)`**: Filters by scope, category, real-world `availableColorId`, helper visibility, and normalized multi-token search query (reusing precomputed `searchText` haystacks), ranking exact ID matches and locally loaded parts first.
- **`buildLibraryColorPalette(colors, options)` / `sortLDrawColorIdsPerceptually()`**: Organizes LDraw colors into finish sections sorted perceptually, optionally filtering to colors with available parts (`onlyAvailable: true` + `availablePartCounts`).
- **`textureStore.clearLibrary()`**: Added to `src/engine/textureStore.ts` so clearing the saved library also evicts library-sourced decal textures without touching `.io`-embedded textures.
